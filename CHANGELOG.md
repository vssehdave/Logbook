# Changelog

## Unreleased

- **A note an agent writes is 3 to 9 lines and carries evidence.** A finding or change note needs an `evidence:` line (what was run or read: a command and its result, or file:line). Naming a file that exists, or a commit, no longer counts as evidence. A one-line note is refused with a message saying what to add, and so is one over nine lines. `--allow-ungrounded` still saves a note with no evidence, marked unverified; the line count has no bypass. A person's own note and a summary note are not held to either rule. The skill now asks for a 2 to 4 sentence summary, not 3 to 5.
- **A note with a commit shows the commit's whole message.** `logbook ask commit:<sha>` prints the subject and body, and an injected note carries a `commit message:` line (subject and body, cleaned like any teammate text, capped at 400 characters). It is read from git each time; the note itself holds only what git does not have.
- Fixed: the reminder to record a note counted only the last checkpoint of a turn, so a `PreCompact` or a second `Stop` inside a turn could zero the reads and the note it had seen. Counts now add up over the turn and start again at the next prompt.
- **Permissions follow the publish mode, with no allow rules.** `logbook setup` now adds one `PreToolUse` hook on Bash instead of writing allow rules into `.claude/settings.local.json` (and removes the 0.0.4 rules). The hook answers only for a command that is exactly one `logbook` command line: reading and private-note commands are allowed; `publish` is denied in mode never, asks in ask, allowed in claude and auto; `sync` asks unless the mode is auto; `purge`, `gc`, `trust`, `config`, `setup` and `uninstall` always ask. A command with a second command, pipe, substitution or redirect gets no answer from it. The table is in the README and is checked against the code.
- **`logbook-scribe`, a subagent that writes the note.** `logbook setup` installs `.claude/agents/logbook-scribe.md` (haiku; never overwrites an agent of the same name that is not ours). The main agent hands it the facts of a turn; it checks them against the code in its own context, writes a note that passes the evidence and size rules, and answers in two lines. When it is installed the reminder tells the agent to hand over the facts, and a hand-off counts as having recorded a note. The permission hook confines it to `note`, `ask`, `context`, `cites`, `log` and `status`. Hooks for a prompt and for a stop do not run inside a subagent (checked), so it cannot set off the reminder again. Whether this beats the agent writing its own note is not measured yet.
- **`logbook tidy` and note statuses.** `logbook tidy` lists notes that may be out of date, repeated or junk, each with the reason: a note whose files changed in a later commit (a change note is about its commit's files, a finding about the files it names), shown with those commits; two notes on the same files that say much the same; an auto-copied draft older than 30 days. `logbook tidy --brief` gives an agent the same list with the notes' words, to judge. `logbook tidy --apply` stores the statuses the person approved: `open`, `in-progress` (shown to agents with the commits that changed it, ranked lower) or `resolved` (never shown to agents again, so never cited). A status is a small separate record written by the note's own author, so the note is not edited and nothing already shared changes; a record from anyone else is ignored, and older versions show the record as an ordinary note. Each proposal must cite commits that exist and touched the note's files after it was written, with a reason, and if one is invalid nothing is stored. `tidy --apply` is the one tidy command Claude Code always asks about; that prompt is the person's approval. Not built yet: the scribe doing the judging, hiding a teammate's note by a trusted writer's status, and deleting or folding old notes.
- A note with a status shows it: `log` marks it `[resolved]` or `[in-progress]` and `ask note:<id>` prints a `status:` line with the commits and the reason. The status record itself is no longer listed as a note of its own. For a decision the user made, the skill (and the scribe) now say the evidence is what they said or chose, quoted briefly.
- Fixed: a Logbook hook could make a person's own `git commit` fail with "Unable to create index.lock". Logbook's background `git status` calls (the hooks on `Stop` and `SessionEnd`, and the detached worker after a commit) refreshed the index, which takes that lock. Every git call Logbook makes now sets `GIT_OPTIONAL_LOCKS=0`, so it only reads. This affected earlier versions too; found when `bench/e2e.py` failed on a second commit made right after the first.
- **A background worker (opt-in): `logbook config worker on`.** After each finished turn a detached process sends the new transcript to a cheap model through your own `claude -p` (no key stored) and writes the few things worth keeping as **private** notes labelled `worker-written`, anchored to the branch and commit. This reverses the earlier rule that Logbook uses no model of its own; it is off by default, never publishes, and a worker note is shown to an agent only when it carries evidence. Python checks each note: evidence that appears in the transcript, nothing named that is not in the repo, 3 to 9 lines, no repeat of an existing note (a repeat of its own earlier note replaces it). Cost is bounded: a quiet turn makes no call, at most 60,000 characters are sent, a daily call cap (`worker_calls`, default 40), and a one-hour pause when the usage allowance runs out. The call runs from an empty directory with settings, MCP servers and slash commands off, and every Logbook hook ignores it (`LOGBOOK_WORKER`). `logbook worker --status` shows spending and the last pass. With the worker on, the agent is no longer reminded to write notes unless `nudge` is set explicitly.
- **Tidy mode: `logbook config tidy manual|auto`.** `logbook tidy --garbage` lists your own private worker drafts that are resolved, about files that are all gone, or older than 30 days (`worker_days`); `--garbage --apply` moves them to `.git/logbook/archive/` (nothing is deleted). In `auto` the worker does that after each pass. Notes a person or an agent wrote are never touched.
- **The observer replaces the per-turn worker (rescope, `docs/RESCOPE.md`).** Every tool use is queued by an async `PostToolUse` hook (no model, no git process) in a running log for the branch it happened on (`.git/logbook/running/<branch>/`). A detached `logbook worker --drain` reads the queue in batches and asks a cheap model, statelessly, for observations (type, title, subtitle, facts, narrative, concepts, files read and modified), skipping what is already recorded. A new branch starts from the main line's observations. Nothing is shared; the savepoint (`logbook log`) comes next. The per-turn transcript notes (`worker-written`) are no longer produced, and the bullets about them above are superseded. After `git pull` of this version, run `logbook setup` again to register the new hooks.
- **`logbook log` is now a savepoint.** It observes what is still queued, summarizes the observations made on this branch since the last savepoint (request, investigated, learned, completed, next steps) and stores a private entry of kind `log`, always filed under the branch and carrying a commit only if one was made since the last savepoint. The summary is written by the cheap model, or by code with `--no-model`. Covered observations move to `running/<branch>/archive/`. **The old view of notes next to commits is `logbook history`** (hidden, still works).
- **Three modes replace four: `manual`, `ask` (default), `auto`** (`logbook config publish`). `never` reads as `manual` and `claude` as `ask`; a stored old value is read, not rewritten. Note the difference for anyone who used `never` to forbid publishing: `manual` lets you publish by hand (`logbook publish`) and only stops the agent; to forbid it for the repo use `"publish": false` in `.logbook/policy.json`. In `ask` the agent is told once per commit to ask whether to save a log; in `auto` a log is saved by itself after a commit that follows 5 or more new observations, and at session end. `auto` still publishes a note as it is written; publishing logs when their branch is merged is not built yet. The band's selector shows `manual ask auto`.
- **Removed: everything that pushed for a note on every commit.** The end-of-turn reminder and block (`nudge`, `nudge_after`, `block_after`), the `logbook-scribe` subagent (setup and uninstall delete a scribe file an earlier pre-release installed, and only if it is ours), `logbook backfill`, `logbook context` (and its "needs a note" check), `note --before-commit` / `before_commit:` (a stale line is accepted and ignored) with the pending-note hook, and the "N of M recent commits say why" counts in `status --check` and `history`. `logbook note` stays for "remember this", and the agent text now says the observer records the session so a note is for what must be kept. Notes of kind `change` and `--commit <sha>` still work.
- **Publishing is by branch.** `logbook publish --branch <name>` and `logbook publish --merged` publish the private logs and notes filed under a branch, once it looks merged (a merge commit names it, or a commit one of its entries is anchored to is in the main line; a squash merge is not detectable from git, so the agent confirms it and names the branch). In `ask` and `auto` mode the agent is told at session start which branches look merged. **`auto` no longer publishes a note the moment it is written**: it publishes with the merge.
- **A pull fetches the shared logs.** `logbook setup` adds `post-merge` and `post-rewrite` git hooks that start a pull-only sync in the background (it never pushes), and `logbook tidy` fetches first (`--no-sync` skips it). Not built: the tidy worker on its own cheap model.
- **Branch memory at session start.** The session-start hook adds the latest trusted logs saved on the current branch and the main line, and what the observer has seen on this branch since its last savepoint, marked as data to verify. The plugin registers the GitHub MCP server (needs `GITHUB_PERSONAL_ACCESS_TOKEN` in the environment; no token is stored).

- **Logbook pauses itself before your subscription allowance runs out, and tells you.** Each background `claude -p` call now runs with `--output-format stream-json --verbose`, and Logbook reads the five-hour and seven-day usage Claude reports in that stream (no API, no key). At 95% of either (`config quota_pause`) the observer and the log summaries stop until the window resets; the next prompt or session start shows you one line (a hook `systemMessage`) with the reason and the resume time and asks the agent to say it too, once per pause. `logbook worker --status` prints the usage and the pause.

- **The tidy worker.** `logbook tidy --work` asks a cheap model (`config tidy_model`, default haiku) whether your notes whose files changed in later commits are `in-progress` or `resolved`; every answer is checked against git before it counts. `config tidy manual` keeps the valid proposals for you (`tidy --proposals`, `tidy --accept`); `config tidy auto` stores them itself, in the background after a log is saved and after a pull, and also folds four or more private logs of a branch into one (`tidy --merge-logs`; originals archived). It shares the observer's daily cap and usage pause. Fixed: `tidy --garbage` would have archived old saved logs as junk drafts, and `tidy auto` did nothing since the observer replaced the old worker.

- **Removed: the per-session and per-commit drafts.** Logbook no longer writes an `auto-copied` note from each session's transcript or for each commit that had none (the old `reconcile` sweep, the spool and the copied transcript slices), and it no longer installs a `post-commit` git hook; `setup` removes the one an earlier version added (only our block, never yours). The observer and `logbook log` are the record of a session. Existing `auto-copied` drafts stay readable, and `tidy --garbage` now lists the old ones among the junk drafts (`--apply` archives them, nothing is deleted). `reconcile` and `install-hook` are gone as commands; an older install's git hook that still calls `post-commit` does nothing and breaks nothing.

- **Fixed: a merged branch's logs disappeared from everyone's context.** Session start showed logs filed under the current branch and the main line only, so once a branch merged its logs were never shown again. Logs of a branch that is in the main line (a merge commit names it, or the log's own commit is in the main line's history) now count as the main line's. A squash merge is not seen.
- **Fixed: the tidy worker no longer judges saved logs** (a session record is history, not a claim to keep true, and marking it `resolved` would have hidden it from session start).
- **Fixed: `claude` is looked up with `which` before it is run**, so a `claude.cmd` shim (an npm install on Windows) works as well as an executable.
- **The band's mode selector in the plugin shows `manual ask auto`** and the plugin version moves with the package, so an installed copy updates.

## 0.0.4

- **Notes go in as `key: value` lines (`logbook note --fields`), not JSON.** In a real session Claude's note was refused because Claude Code flags `{"` in a shell command as obfuscation and needs a person to approve it, whatever allow rules exist, so an unattended agent could never save a note (and an attended one was prompted every time). The skill, rules and prompts now use `--fields`; `--json` still works.
- **Fixed: the "record a note" prompt never came.** The hook decided Claude had already written a note when a command merely contained the word note, so Claude's own `logbook ask "... same note id"` switched the prompt off. Only the `note` subcommand counts now. Found by running a real Claude session on a real question, where it never wrote a note; our earlier 4-of-4 measurement used a toy transcript and missed it.
- **Fewer prompts.** `logbook setup` now adds allow rules for the commands that only read or write your private notes (`note`, `ask`, `context`, `cites`, `log`, `status`, `summarize`, `backfill`) to `.claude/settings.local.json`, so Claude Code stops asking before each one. Sharing, removing and changing settings (`publish`, `sync`, `purge`, `gc`, `trust`, `config`) still ask. `logbook uninstall` removes only those entries. The skill's note example is now a heredoc so one rule covers it.
- **A note in plain words.** `logbook note "late export dips revenue" shop/revenue.py` is a whole note: the words, then the files. A person's own note needs no why and no evidence and is shown to the agent as it is; the evidence rule is for notes an agent wrote.
- **Note quality gates.** `logbook note --check` looks up what a note names (the files it concerns, the names in backticks, the commit ids) in the repo and reports `grounding: files 2/2, names 3/4, ...`, and lists notes on the same files that say much the same. A finding that names no file that exists, no commit and no evidence is refused (`--allow-ungrounded` overrides). The result is saved and published with the note; an injected note that names something that is not there is labelled `unverified` and ranks lower, and auto mode does not share it on its own. Notes can now supersede your own earlier notes (`"supersedes": [ids]`, `--supersedes`). This checks that what a note names exists, not that what it says is true.
- **"agent-written" now means Claude wrote it.** Every note used to be labelled agent-written, including the ones a person typed. A note is now `agent-written` only when it is written from inside an agent's session (Claude Code puts its session id in the environment of the commands it runs) and `user-written` otherwise. `LOGBOOK_WRITER=agent` or `=user` says it outright, for another agent or for a person using an agent's shell. Notes written by earlier versions keep their claim but are shown as `origin unknown`, because there is no way to tell. The label is published with the note.
- `logbook cites --where N` prints, as JSON, every answer in a Claude Code chat that cites number N (the transcript row's id and the words around the citation), read from Claude Code's transcript. The band uses it for its peek, so clicking a citation works for every answer in the chat, on screen or not.
- Publish modes: `logbook config publish never|ask|claude|auto` (default `ask`). never: `publish` refuses. ask: you confirm a redacted preview each time, as before. claude: the agent may publish a note it judges worth sharing, without asking you. auto: every note is published to your local shelf as it is written, redacted the same way; a note the checks refuse stays private. Pushing is still `logbook sync` in every mode, and redaction is a lint that can miss secrets. A repo policy that turns publishing off wins over any mode. The agent's rules and skill say which mode means what, and `logbook cites --json` reports the mode for the band.
- **Security fix (affects 0.0.2 and 0.0.3).** A shared note's commit, tree, parent and merge-base ids came from the note and went into `git` arguments unchecked. An id such as `--output=<path>` made `git show` overwrite that file on the reader's machine, which `logbook cites`, the injected source lines and `ask` could trigger for a note from any writer you read. Those ids are now accepted only as hex when an entry is read, and the git helpers refuse anything else too. Upgrade, and treat shared refs from writers you do not trust with care until you have.
- Citations are written as a bare superscript number (¹ ² ³), and the band uses the same label. `commit_url` and `pr_url` in the config give links for hosts Logbook does not know; a header that names a pull request falls back to the commit when there is no pull request address.
- Changed back: `git push` no longer sends your notes. `logbook sync` is the one command that pushes them (it also fetches teammates' notes and merges your other machines). The pre-push hook only reminds you, now also of notes you published but have not pushed. In 0.0.3 the hook pushed notes too, and with it installed `logbook sync` could be rejected ("incorrect old value provided") because the same ref was pushed twice. If you installed 0.0.3, run `logbook setup --yes` to replace the old hook.
- Fixed: `logbook publish` with no ids printed a traceback when there was no answer to read (closed input). It now takes that as no answer.
- The compact label in `logbook cites` and the band is the note's own title, not the commit subject; the commit or pull request header moves to the expanded line.

## 0.0.3

- An optional Claude Code plugin in this repo (`.claude-plugin/`, `hooks/band/`): a Sources band above the prompt with Copy and expand/compact, showing the notes the latest answer cited and, for a teammate's shared notes, the link, author and date. Install with `/plugin install logbook --marketplace vssehdave/Logbook`.
- Citations. Notes put in front of an agent are numbered for the whole chat, and the agent cites them as superscripts (¹ ² ³). `logbook cites` maps a number back to the note, a link to the commit or pull request (GitHub, GitLab, Bitbucket, or a `commit_url` template in the config), the author and the date. Links and names are given only for notes a teammate shared; your own and private notes get none. A shared note with no commit reads "Note added by <name> on <date>".
- The repo is a tree you can walk: `repo` > `branch:<name>` > `commit:<sha>` > `note:<id>`. `logbook ask <address>` opens a node with its path from the root, its summary and what is below it; injected notes name their node. See `docs/SUMMARY-TREE.md`.
- A note written before its branch had a commit now follows a squash merge once the branch is gone (same files, first PR-numbered commit after the branch point); the rung says so.
- `wip`, `fixup!`, `squash!` and `amend!` commits are folded out of `logbook log` like chores.
- The skill says where a note belongs: long research on the branch, a short note on each commit.
- Seven commands to learn: `setup`, `note`, `publish`, `sync`, `ask`, `log`, `status`. `ask` takes a revision range, an id, a file or name, or free text. `log` shows the notes next to your commits in the terminal. `status --check` and `--stats` fold in `doctor` and `stats`. Every older name (`init`, `join`, `install`, `query`, `explain`, `path`, `doctor`, `queue`, `stats`, and the hook entry points) still runs, so existing installs keep working; they are just not listed in `--help`.
- Removed the browser viewer (`logbook serve`, `demo --serve`). It lives on the `viewer` branch.
- One shared shelf per person instead of one per clone. Two machines of the same person merge on `sync`. Old per-device refs are still read and are folded into the shelf on the next publish or sync (the old names are deleted on the remote after the push).
- `logbook publish` moves the note: the private copy is removed once the shared copy exists (`--keep` leaves it). It skips a note that is already shared, and one whose text a teammate already shared (`--force` overrides). With no ids it lists your unshared notes and asks which.
- The pre-push hook now pushes your published notes with the push (it never blocks, times out after 20 s, and only sends what you published). `logbook install` also adds the fetch setting so a plain `git pull` brings teammates' notes.
- Names are shown by default (`attribution: named`). A person can set `pseudonym`, and a repo's `.logbook/policy.json` can cap it.

## 0.0.2

Logbook now helps the agent write the notes, instead of leaving it to chance.

### Changed (read this when upgrading)

- Notes no longer know about dbt models or layers. An anchor carries `names` (file names) in place of `models`; entries written by
  0.0.1 still load, their `models` become `names` and their `layers` are ignored.
- The `inferred` provenance is now `auto-copied`; files that say `inferred` load as `auto-copied`.
- `logbook install` sets everything up and asks first (`--yes` applies, `--dry-run` only looks). `--write` still works as `--yes`.
  The old hooks-only behaviour is now one step of it.
- The default size cap for a published note is 32,768 bytes (was 16,384) because notes can be longer.
- The Stop hook now asks Claude Code once to record a note before it finishes a turn that read or searched three or more times and
  wrote none. `logbook config nudge context` makes it a reminder on the next prompt, `off` removes it.

### Added

- One-command setup and removal: git post-commit and pre-push hooks, Claude Code hooks, a skill, and an always-on rules block for
  Claude Code, `AGENTS.md`, Copilot, Gemini and Cursor. Backups, atomic writes, symlink and line-ending safe, `uninstall`.
- Richer notes: `context`, `decided`, `open`, `scale`, a longer `summary`, `sources`, `level`. `logbook note --json` reads a whole
  note from stdin; `--commit <sha>` writes about an earlier commit; `--sources` cites findings.
- Following notes through a merge, a rebase, and a squash; a note about a branch's work waits with the branch until its merge.
- Coverage: chores, merges and whitespace or rename-only commits count as covered; `logbook doctor` counts the rest.
- `logbook context`, `logbook backfill`, `logbook summarize`, `logbook queue`, `logbook publish --all`, `logbook config`.
- Summaries of the repo or a branch, written by the agent, shown at session start while fresh.
- Prompt matching on free text, not only on file names.
- `bench/run_ab.py` (notes against none, and unprompted note-writing); real Claude Code hook payloads
  as test fixtures.

### Known limits

- Hooks exist only for Claude Code. A note written before its branch's first commit is lost to a squash merge.
- The measurements are two small smoke tests on a toy repo, not evidence about real work.
